## Regressions / surprises

1. **2.5 day selector affordance incomplete** — the plan specified "1.5 days of Sunday peeking from the right edge", but the My Plan day selector clips at Sat with Sun fully off-screen. In light mode I did see a right-edge fade, but the peek itself is missing. Low-severity functional issue — scroll still works, users can access Sunday — but the affordance intent isn't fully realized.

2. **Home scroll stuck mid-QA** — After a rapid sequence of tab-switch taps (Home → Profile → Settings → Home → Meals → Home), the Home scroll view appeared not to respond to swipe gestures from Maestro or idb in one session. Re-entering via tab-switch fixed it. Worth monitoring on physical device.

3. **Metabolic toggle confirmed 7.3** — Track → Metabolic pill tap completely unresponsive to both idb and Maestro text selector. Pass-2 guess ("hit-target size bug") is probably correct — likely the `TouchableOpacity` has either too-small a hit area or a parent container intercepting touches. **Recommend investigation on real hardware before ship.**

4. **Segmented control missing accessibility roles** — The Appearance segmented control (System / Light / Dark in Settings) has no `accessibilityRole="button"` labels — Maestro `tapOn: "Light"` failed and `idb ui describe-all` didn't surface them. Users with VoiceOver will not be able to distinguish these buttons. **Minor a11y bug found during QA — worth a quick fix** (Phase 7.2 follow-on: add `accessibilityRole="button"` + `accessibilityState={{ selected: mode === 'light' }}` to each pill).
